# Supply Prescript — Week 2 Validation

## Purpose

This document defines the validation checks for the Week 2 optimization,
constraints, prescription alternatives, and decision execution requirements.

Tests are not marked PASS without actual implementation and verification
evidence.

---

## Test W2-01 — Optimization Exists

### Requirement

Verify that the project contains a real SciPy optimization implementation.

### Checks

- [ ] SciPy is used by the optimization implementation.
- [ ] The solver executes successfully.
- [ ] The solver returns a valid optimization result.
- [ ] The result is generated by the solver and is not hard-coded.

### Expected Result

The SciPy optimization solver executes successfully and returns a valid
result.

### Status

PENDING — implementation evidence required.

### Evidence

- Terminal output
- Test output
- Relevant implementation path
- Solver result

---

## Test W2-02 — Budget Constraint

### Requirement

Verify that the optimization respects the configured maximum budget.

### Checks

- [ ] Input a case with a limited budget.
- [ ] Solver generates a valid recommendation within the budget.
- [ ] Recommended cost is less than or equal to the configured maximum budget.
- [ ] Test an intentionally impossible or over-budget case.
- [ ] Solver does not silently return an invalid recommendation.

### Expected Result

For a feasible case:

`recommended cost <= configured maximum budget`

For an impossible case, the system must clearly indicate that no valid
recommendation is available or otherwise handle the constraint failure.

### Status

PENDING — solver implementation and test evidence required.

### Evidence

- Test input
- Solver output
- Constraint validation output
- Screenshot if applicable

## Test W2-06 — Cost vs Speed

### Requirement

Verify that every generated alternative contains actual cost and speed/time
values.

### Checks

- [ ] Option 1 contains an actual cost value.
- [ ] Option 1 contains an actual speed/time value.
- [ ] Option 2 contains an actual cost value.

## Test W2-07 — Execute Decision

### Requirement

Verify that clicking `Execute Decision` eventually results in a real database
INSERT.

### Checks

- [ ] User can select a recommendation.
- [ ] Execute Decision action is available when backend support exists.
- [ ] Execute Decision calls the backend write-back endpoint.
- [ ] Backend receives the selected decision.
- [ ] Database INSERT is executed.
- [ ] Inserted decision can be retrieved from the database.

### Status

BLOCKED

### Dependency

Backend write-back endpoint and database implementation.

### Expected Result

Executing a decision creates a real database record.

### Evidence Required

- UI screenshot
- API request/response
- Backend log or test output
- Database query result

Do not mark PASS until actual database evidence exists.

## Test W2-08 — Evidence Requirement

### Requirement

Every test marked PASS must have supporting implementation and verification
evidence.

### Required Evidence

For every PASS test, provide one or more of:

- [ ] Terminal output
- [ ] Test output
- [ ] Screenshot
- [ ] Database query result
- [ ] API response
- [ ] Relevant implementation path

### Evidence Rule

Documentation alone is not sufficient evidence for PASS.

A planned implementation, placeholder, hard-coded value, or mock result must
not be treated as proof of completion.

### Status

PENDING — evidence will be added when implementation is available.
